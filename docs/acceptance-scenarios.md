# Acceptance Scenarios

Данный документ описывает acceptance сценарии для проверки функциональности системы.

## Exams (Экзамены)

### Сценарий 1: Создание экзамена и обработка результатов

**Предусловия:**
- Пользователь с ролью "методист" авторизован
- Существует группа студентов
- Существует предмет
- Существует комната

**Шаги:**

1. **Создание экзамена**
   - Перейти на `/exams/new`
   - Заполнить форму:
     - Type: `exam`
     - Title: "Экзамен по математике"
     - Subject: выбрать предмет
     - Group: выбрать группу
     - Date: выбрать дату в будущем
     - Room: выбрать комнату
   - Нажать "Создать"
   - **Ожидаемый результат:** Экзамен создан, отображается в списке экзаменов

2. **Seed registrations**
   - Открыть экзамен
   - Перейти на вкладку "Допуски"
   - Нажать "Создать регистрации для группы"
   - **Ожидаемый результат:** Для всех студентов группы созданы регистрации со статусом `registered`

3. **Пересчитать допуски**
   - На вкладке "Допуски" нажать "Пересчитать допуски"
   - Система проверяет для каждого студента:
     - Просроченные задания (debts_high)
     - Посещаемость за семестр/30 дней
     - Средний балл за семестр
   - **Ожидаемый результат:** 
     - Часть студентов получили статус `admitted` (если нет долгов, посещаемость в норме, средний балл достаточен)
     - Часть студентов получили статус `not_admitted` с указанием причины (например, "Превышен лимит долгов", "Низкая посещаемость", "Низкий средний балл")

4. **Назначение комиссии**
   - Перейти на вкладку "Комиссия"
   - Добавить участников комиссии:
     - Председатель (role: `chair`)
     - Члены комиссии (role: `member`)
   - Нажать "Сохранить"
   - **Ожидаемый результат:** Комиссия назначена, отображается список участников

5. **Выставление результатов**
   - Перейти на вкладку "Результаты"
   - Для каждого студента ввести:
     - Score (балл, опционально)
     - Grade (оценка: 2, 3, 4, 5)
     - Comment (комментарий, опционально)
   - Нажать "Сохранить" для каждого студента
   - **Ожидаемый результат:** Результаты сохранены, отображаются в таблице

6. **Формирование ведомости**
   - На вкладке "Ведомость" нажать "Сформировать ведомость"
   - **Ожидаемый результат:** 
     - Создан Document типа `grade_sheet`
     - Отображается `documentId`
     - В `data_json` документа содержится:
       - Информация об экзамене
       - Список комиссии
       - Список студентов с результатами
       - Подписи

7. **Экспорт ведомости**
   - Нажать "Export DOCX" или "Export PDF"
   - **Ожидаемый результат:** 
     - Файл скачивается
     - Файл содержит ведомость с данными экзамена, комиссией, списком студентов и результатами

## Contests (Конкурсы)

### Сценарий 2: Создание конкурса и подведение итогов

**Предусловия:**
- Пользователь с ролью "методист" авторизован
- Существуют студенты/группы для назначения targets
- Существуют пользователи для назначения в жюри

**Шаги:**

1. **Создание конкурса**
   - Перейти на `/contests/new`
   - Заполнить форму:
     - Title: "Конкурс программирования"
     - Description: "Описание конкурса"
     - Start date: дата начала
     - End date: дата окончания
     - Visibility scope: `all` или `group`
   - Нажать "Создать"
   - **Ожидаемый результат:** Конкурс создан

2. **Создание рубрики**
   - Открыть конкурс
   - Перейти на вкладку "Рубрика"
   - Добавить критерии:
     - Критерий 1: "Алгоритм" (maxScore: 30, weight: 1.0)
     - Критерий 2: "Код" (maxScore: 30, weight: 1.0)
     - Критерий 3: "Документация" (maxScore: 20, weight: 0.5)
     - Критерий 4: "Презентация" (maxScore: 20, weight: 0.5)
   - Нажать "Сохранить"
   - **Ожидаемый результат:** Рубрика создана, критерии отображаются

3. **Назначение targets (участников)**
   - Перейти на вкладку "Участники"
   - Добавить группы или отдельных пользователей
   - Нажать "Сохранить"
   - **Ожидаемый результат:** Участники назначены, отображаются в списке

4. **Назначение жюри**
   - Перейти на вкладку "Жюри"
   - Добавить участников жюри:
     - Председатель (role: `chair`)
     - Члены жюри (role: `member`)
   - Нажать "Сохранить"
   - **Ожидаемый результат:** Жюри назначено

5. **Отправка работы студентом**
   - Выйти из системы методиста
   - Войти как студент (из числа targets)
   - Открыть конкурс
   - Нажать "Отправить работу"
   - Заполнить форму:
     - Title: "Моя работа"
     - Description: "Описание работы"
     - Загрузить файл(ы)
   - Нажать "Отправить"
   - **Ожидаемый результат:** 
     - Submission создан
     - Файлы загружены
     - Работа отображается в списке работ

6. **Оценивание работы жюри**
   - Выйти из системы студента
   - Войти как член жюри
   - Открыть конкурс
   - Перейти на вкладку "Работы"
   - Выбрать работу
   - Заполнить оценку по критериям:
     - Алгоритм: 25
     - Код: 28
     - Документация: 18
     - Презентация: 19
   - Добавить комментарий (опционально)
   - Нажать "Сохранить оценку"
   - **Ожидаемый результат:** 
     - Оценка сохранена
     - Автоматически рассчитан `total_score` с учётом весов
     - Оценка отображается в списке оценок

7. **Публикация результатов**
   - Выйти из системы жюри
   - Войти как методист
   - Открыть конкурс
   - Перейти на вкладку "Результаты"
   - Нажать "Опубликовать результаты"
   - **Ожидаемый результат:** 
     - Для каждой работы рассчитан `final_score` (среднее от всех оценок жюри)
     - Присвоены места (place) по убыванию final_score
     - Установлен `published_at`
     - Участники уведомлены

8. **Генерация сертификатов**
   - На вкладке "Сертификаты" нажать "Сгенерировать сертификаты"
   - **Ожидаемый результат:** 
     - Для каждого участника/победителя создан Document типа `certificate`
     - В `data_json` содержится:
       - ФИО участника
       - Название конкурса
       - Место (если есть)
       - Финальный балл
       - Дата
     - Отображается список `{userId, documentId}`

9. **Скачивание сертификата**
   - Выбрать сертификат из списка
   - Нажать "Скачать DOCX" или "Скачать PDF"
   - **Ожидаемый результат:** 
     - Файл сертификата скачивается
     - Файл содержит данные участника, конкурса, место и балл

## Import/Export

### Сценарий 3: Импорт пользователей

**Предусловия:**
- Пользователь с ролью "admin" авторизован
- Подготовлен XLSX файл с колонками: `fio`, `email`, `phone`, `role`, `group` (опционально)

**Шаги:**

1. **Импорт users-xlsx**
   - Перейти на страницу импорта (или `/admin/import/users-xlsx`)
   - Выбрать XLSX файл
   - Нажать "Импортировать"
   - **Ожидаемый результат:** 
     - Новые пользователи созданы
     - Роли назначены
     - Пользователи добавлены в группы (если указано)
     - Отображается `success_count` и список ошибок (если есть) с номерами строк

**Пример XLSX:**
```
fio              | email              | phone        | role    | group
Иванов Иван      | ivanov@example.com | +79001234567 | student | Группа 1
Петров Петр      | petrov@example.com | +79001234568 | teacher | 
```

### Сценарий 4: Экспорт расписания

**Предусловия:**
- Пользователь с ролью "admin" авторизован
- Существует schedule_version с items

**Шаги:**

1. **Экспорт schedule-xlsx**
   - Перейти на страницу экспорта (или `/admin/export/schedule-xlsx?versionId=1`)
   - Нажать "Экспортировать"
   - **Ожидаемый результат:** 
     - XLSX файл скачивается
     - Файл содержит колонки: `date`, `time_slot`, `group`, `subject`, `teacher_email`, `room`
     - Данные соответствуют выбранной версии расписания

## Webhooks

### Сценарий 5: Настройка и тестирование webhook

**Предусловия:**
- Пользователь с ролью "admin" авторизован
- Подготовлен endpoint для приёма webhook (например, requestbin.io или локальный сервис)

**Шаги:**

1. **Создание webhook endpoint**
   - Перейти на `/admin/webhooks`
   - Нажать "Добавить webhook"
   - Заполнить форму:
     - Name: "Schedule Changes"
     - URL: `https://requestbin.io/r/xxxxx` (или локальный URL)
     - Secret: оставить пустым (сгенерируется автоматически) или указать свой
     - Enabled: включено
     - Event types: выбрать `schedule.changed`
   - Нажать "Сохранить"
   - **Ожидаемый результат:** 
     - Webhook endpoint создан
     - Secret сгенерирован (если не указан)
     - Отображается в списке webhooks

2. **Изменение расписания**
   - Перейти на страницу расписания
   - Создать или изменить schedule item
   - Сохранить изменения
   - **Ожидаемый результат:** 
     - Событие `schedule.changed` отправлено в outbox
     - Job `DeliverWebhooks` обработал событие
     - Создана запись в `webhook_deliveries` со статусом `pending` или `sent`
     - POST запрос отправлен на указанный URL с:
       - Телом: `{eventId, eventType, actorUserId, entityType, entityId, payload, createdAt}`
       - Заголовком `X-Signature` с HMAC SHA256 подписью

3. **Проверка доставки**
   - Проверить endpoint (requestbin или логи локального сервиса)
   - **Ожидаемый результат:** 
     - Запрос получен
     - Тело запроса содержит данные события
     - Подпись в заголовке `X-Signature` валидна (можно проверить локально)

4. **Проверка статуса доставки**
   - Вернуться на `/admin/webhooks`
   - Открыть созданный webhook
   - Просмотреть deliveries
   - **Ожидаемый результат:** 
     - Отображается delivery со статусом `sent` (если успешно) или `failed` (если ошибка)
     - Указано количество попыток (`attempts`)
     - Если ошибка, указан `last_error`

## Load Testing

### Сценарий 6: Запуск smoke test

**Предусловия:**
- Backend запущен и доступен
- Подготовлены тестовые пользователи

**Шаги:**

1. **Запуск smoke test**
   - Через Docker Compose:
     ```bash
     docker compose --profile loadtest up k6-smoke
     ```
   - Или локально:
     ```bash
     cd loadtest/k6
     k6 run --out json=../results/smoke.json smoke.js
     ```
   - **Ожидаемый результат:** 
     - Тест выполнен
     - Результаты сохранены в `loadtest/results/smoke.json`

2. **Генерация отчёта**
   - Выполнить:
     ```bash
     cd loadtest/k6
     node generate-report.js ../results/smoke.json
     ```
   - **Ожидаемый результат:** 
     - Выведен отчёт с:
       - Total Requests
       - Latency Metrics (Average, Min, Max, **p95**)
       - Error Metrics (Error Count, **Error Rate**)
       - Статус PASS/FAIL для порогов

3. **Проверка порогов**
   - **Ожидаемый результат:** 
     - p95 latency < 500ms (порог для smoke test)
     - Error rate < 10%
     - Статус: ✅ PASS

## Чек-лист для проверки

- [ ] Exams: создание экзамена, seed registrations, пересчёт допусков, выставление результатов, формирование и экспорт ведомости
- [ ] Contests: создание конкурса, рубрика, targets, jury, отправка работы, оценивание, публикация результатов, генерация и скачивание сертификатов
- [ ] Import: импорт users-xlsx создаёт новых пользователей с ролями и группами
- [ ] Export: экспорт schedule-xlsx отдаёт корректный файл
- [ ] Webhooks: создание endpoint, отправка при изменении расписания, проверка доставки и подписи
- [ ] Loadtest: smoke test проходит, p95 фиксируется в отчёте

---

## Примечания

- Все сценарии предполагают наличие тестовых данных (пользователи, группы, предметы и т.д.)
- Для webhook тестирования рекомендуется использовать [requestbin.io](https://requestbin.io) или локальный сервис для приёма запросов
- Для load testing убедитесь, что backend запущен и доступен по указанному BASE_URL
- При ошибках проверьте логи: `backend/storage/logs/laravel.log` и `backend/storage/logs/slow.log`
