# PDO Monorepo

Монорепозиторий для приложения на стеке:
- **Backend**: Laravel 11+ (PHP 8.2), PostgreSQL, Redis, MinIO, WebSocket, очередь (outbox + broadcaster)
- **Frontend**: Vue 3 + TypeScript + Pinia + Vue Router + Vuetify + Vite
- **Infra**: Docker Compose, Nginx, php-fpm, queue-worker, WebSocket, Vite dev server

## Структура

```bash
.
├── backend/        # Laravel backend
├── frontend/       # Vue 3 + TS + Vuetify frontend
├── infra/          # docker-compose, nginx и прочая инфраструктура
├── docs/           # архитектура, события, контракты
├── websocket/      # Laravel Echo Server / WebSocket сервис
├── docker-compose.yml
└── README.md
```

## Быстрый старт (dev)

```bash
# 1. Скопировать и настроить окружение
cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env

# 2. Запустить инфраструктуру (из корня репо)
docker compose up -d --build

# 3. Выполнить миграции и базовую настройку Laravel
docker compose exec php-fpm php artisan migrate
docker compose exec php-fpm php artisan storage:link

# 4. Заполнить базу демо-данными (опционально)
docker compose exec php-fpm php artisan db:seed

# Или запустить конкретный сидер:
docker compose exec php-fpm php artisan db:seed --class=DemoDataSeeder
```

## Основные сервисы

- `nginx`      — входная точка, проксирует Vite dev server и Laravel API
- `php-fpm`    — Laravel backend
- `queue-worker` — обработчик очередей (Laravel queue, TODO: Horizon)
- `postgres`   — основная БД (bigint PK, snake_case таблицы)
- `redis`      — кеш, очереди, WS
- `minio`      — S3-совместимое хранилище
- `ws`         — WebSocket сервис (Laravel Echo Server)
- `frontend`   — Vite dev server для Vue 3

### 1. Документы (Document Workflow)

**Сценарий**: Полный цикл создания и утверждения документа

1. **Создание документа** (Admin):
   - Перейти в раздел "Документы"
   - Создать новый документ из шаблона
   - Заполнить необходимые поля

2. **Назначение маршрута** (Admin):
   - Назначить маршрут согласования
   - Добавить участников: approver, руководство, адресаты

3. **Согласование** (Approver):
   - Получить уведомление о необходимости согласования
   - Просмотреть документ
   - Нажать "Approve" (одобрить)

4. **Подписание** (Руководство):
   - Получить уведомление о необходимости подписания
   - Просмотреть документ
   - Нажать "Sign" (подписать)

5. **Подтверждение** (Адресаты):
   - Получить уведомление о документе
   - Просмотреть документ
   - Нажать "Confirm" (подтвердить получение)

6. **Экспорт** (Admin/Authorized):
   - После завершения всех этапов
   - Нажать "Экспорт DOCX"
   - Скачать готовый документ

### 2. Расписание (Schedule Versioning)

**Сценарий**: Создание и публикация новой версии расписания

1. **Создание черновика** (Admin):
   - Перейти в "Расписание"
   - Выбрать "Создать черновик" (draft)
   - Выбрать версию-источник (опционально)

2. **Внесение изменений**:
   - Добавить/изменить/удалить пары
   - Изменить время, кабинет, преподавателя
   - Сохранить изменения

3. **Просмотр истории изменений**:
   - Перейти на вкладку "История изменений"
   - Просмотреть таблицу: дата/время, действие, автор, краткое описание

4. **Сравнение версий**:
   - Перейти на страницу "Сравнение версий"
   - Выбрать версию "From" и "To"
   - Просмотреть списки: добавлено, удалено, изменено

5. **Публикация**:
   - Нажать "Опубликовать" (publish)
   - Подтвердить действие
   - Старая версия автоматически архивируется (archived)
   - Показать toast-уведомление об успехе

### 3. КТП (Curriculum Planning)

**Сценарий**: Создание плана КТП и отслеживание прогресса

1. **Создание плана** (Методист/Учитель):
   - Перейти в раздел "КТП"
   - Нажать "Создать план"
   - Выбрать: предмет, группа, семестр

2. **Добавление тем (bulk)**:
   - Нажать "Добавить темы"
   - Вставить 10+ строк сразу (bulk)
   - Заполнить: порядковый номер, название, часы, тип контроля, планируемые даты

3. **Привязка ресурсов**:
   - Выбрать тему в таблице
   - В панели "Связи" привязать:
     - Assignment (задание)
     - Material (материал)
     - Lesson (урок)
   - Повторить для других тем

4. **Просмотр прогресса**:
   - В верхней части страницы видеть:
     - Процент выполнения (total_topics, linked_topics_count)
     - Alerts: список проблем (например, темы с control_type=control, но без assignment/grade)

5. **Операции с планом**:
   - Применить шаблон к плану
   - Скопировать из прошлого семестра
   - Редактировать темы (перетаскивание или кнопки вверх/вниз для reorder)

### 4. Чат (Chat Moderation)

**Сценарий**: Модерация чата и работа с жалобами

1. **Режим объявлений** (Модератор/Admin):
   - Открыть чат
   - Нажать кнопку настроек (шестеренка)
   - Переключить режим на "Объявления" (announcements)
   - Сохранить
   - **Результат**: Обычные пользователи не могут писать, только модераторы

2. **Тихие часы** (Модератор/Admin):
   - В настройках чата включить "Тихие часы"
   - Добавить период (например, 22:00 - 08:00)
   - Сохранить
   - **Результат**: В указанное время обычные пользователи не могут отправлять сообщения (модераторы могут)

3. **Жалоба на сообщение** (Любой пользователь):
   - В чате найти сообщение
   - Нажать меню (три точки) у сообщения
   - Выбрать "Пожаловаться"
   - Ввести причину жалобы
   - Отправить

4. **Просмотр жалоб** (Admin/Модератор):
   - Перейти в "Админка" → "Жалобы на сообщения"
   - Просмотреть таблицу: thread, message snippet, reported_by, status, createdAt
   - Выполнить действия:
     - Пометить как "reviewed" (просмотрено)
     - Пометить как "closed" (закрыто)
     - Перейти в чат для просмотра контекста

### 5. PWA (Progressive Web App)

**Сценарий**: Установка приложения и настройка push-уведомлений

1. **Установка PWA**:
   - Открыть приложение в браузере
   - Должно появиться предложение установить приложение
   - Нажать "Установить"
   - **Результат**: Приложение устанавливается как standalone приложение

2. **Push-подписка**:
   - Войти в систему
   - Перейти в меню пользователя → "Настройки уведомлений"
   - Нажать "Включить push-уведомления"
   - Разрешить уведомления в браузере
   - **Результат**: 
     - Подписка создается и сохраняется в базе данных
     - Статус показывает "Push-уведомления включены"
     - Отображается информация о поддержке браузера и разрешениях

3. **Проверка подписки**:
   - В настройках уведомлений видеть:
     - Статус поддержки браузера
     - Статус разрешения уведомлений
     - Информацию об активной подписке

**Примечание**: Для полной работы push-уведомлений необходимо:
- Настроить VAPID ключи в `.env` (backend и frontend)
- Использовать HTTPS в production (push требует HTTPS)

### 6. Pack #8 – Product and Pedagogical Level

**Сценарии**: Функциональность уровня продукта и педагогики

#### 6.1. Timeline (История обучения)

**Сценарий**: Просмотр истории обучения студента

1. **Открытие Timeline** (Студент/Родитель/Куратор/Методист/Admin):
   - Перейти на страницу студента → "История обучения"
   - **Результат**: Отображается timeline с событиями:
     - Оценки (создание, изменение)
     - Пропуски (отметки о посещаемости)
     - Риски (изменение уровня риска на red/yellow)
     - Приказы (документы, связанные со студентом)

2. **Фильтрация событий**:
   - Выбрать тип события (оценки, пропуски, риски, приказы)
   - Указать период (дата начала, дата окончания)
   - Применить фильтры
   - **Результат**: Отображаются только выбранные типы событий за указанный период

3. **Экспорт истории**:
   - Нажать "Экспорт истории"
   - **Результат**: Скачивается PDF с историей обучения, сгруппированной по месяцам

#### 6.2. Personal Assistant (Ассистент "Что делать сегодня")

**Сценарий**: Получение задач на сегодня в зависимости от роли

1. **Для студента**:
   - Перейти на Dashboard
   - **Результат**: Отображаются:
     - Пары на сегодня
     - Дедлайны (24ч/3д)
     - Просроченные задания
     - Риски (red/yellow)
     - Непрочитанные материалы

2. **Для преподавателя**:
   - Перейти на Dashboard
   - **Результат**: Отображаются:
     - Пары на сегодня
     - Непроверенные работы
     - Уроки без оценок
     - Студенты с красным риском

3. **Для куратора**:
   - Перейти на Dashboard
   - **Результат**: Отображаются:
     - Посещаемость сегодня
     - Новые риски (за последние 7 дней)
     - Долги по группе
     - Студенты с низким средним баллом (avg <= 2)

4. **Для администратора**:
   - Перейти на Dashboard
   - **Результат**: Отображаются:
     - Документы на согласовании

#### 6.3. Student Portfolio (Портфолио студента)

**Сценарий**: Автоматическое наполнение портфолио

1. **Автоматическое добавление из конкурсов**:
   - Опубликованы результаты конкурса
   - Студент занял призовое место (1, 2, 3)
   - **Результат**: Результат автоматически добавляется в портфолио студента с типом "contest"

2. **Автоматическое добавление сертификатов**:

   - Документ связан со студентом
   - **Результат**: Сертификат автоматически добавляется в портфолио с типом "certificate"

3. **Автоматическое добавление заданий**:
   - Студент получил оценку >= 4.0 за задание
   - **Результат**: Задание автоматически добавляется в портфолио с типом "assignment"

4. **Просмотр портфолио**:
   - Перейти на страницу студента → "Портфолио"
   - **Результат**: Отображаются все элементы портфолио с возможностью фильтрации по типу

5. **Экспорт портфолио**:
   - Нажать "Экспорт портфолио"
   - **Результат**: Скачивается PDF с портфолио, сгруппированным по типам

## Мониторинг (Dev Profile)

### Prometheus & Grafana

Мониторинг доступен в профиле `dev`:

```bash
docker compose --profile dev up -d prometheus grafana
```

### Доступ

- **Grafana**: http://localhost:3001
  - Учетные данные по умолчанию: `admin` / `admin` (изменить через `GRAFANA_ADMIN_PASSWORD`)
- **Prometheus**: http://localhost:9090

### Метрики

Приложение экспортирует метрики в формате Prometheus на `/api/metrics`. Prometheus настроен на сбор метрик каждые 15 секунд.

### Grafana Dashboard

Базовый dashboard автоматически подключается:
- **Расположение**: Dashboards → PDO System Overview
- **Ключевые метрики**:
  - Request Rate (запросов/сек)
  - Request Duration (p95, p50 latency)
  - Error Rate (4xx, 5xx ошибки)
  - Database Queries
  - Active Users

### Просмотр метрик

1. **Открыть Grafana**: http://localhost:3001
2. **Войти** с учетными данными admin
3. **Перейти**: Dashboards → PDO System Overview
4. **Ключевые панели**:
   - **p95 Latency**: Статистика в правом верхнем углу показывает текущую p95 latency
   - **Error Rate**: График в левом нижнем углу показывает 4xx и 5xx ошибки во времени
   - **Request Duration**: График в правом верхнем углу показывает тренды p95 и p50 latency

### Конфигурация

- Prometheus config: `infra/prometheus/prometheus.yml`
- Grafana datasource: `infra/grafana/provisioning/datasources/prometheus.yml`
- Dashboards: `infra/grafana/dashboards/`

### Переменные окружения

```env
PROMETHEUS_PORT=9090
GRAFANA_PORT=3001
GRAFANA_ADMIN_USER=admin
GRAFANA_ADMIN_PASSWORD=admin
```
